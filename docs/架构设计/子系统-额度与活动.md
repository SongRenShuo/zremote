## 1. 职责边界

额度/套餐/余额的查询与归一化展示、套餐重置卡、福利中心内嵌页。**不做**：领取调度（领取调度域）、账号凭据（账号与授权域）。

## 2. 两条数据通路

### 2.1 通路 A：宿主 RPC（默认，免 token）

`usage-stats` 频道 `getEntitlementSnapshot`（既有先例：model_settings_page 套餐配额行）。

### 2.2 通路 B：直连 HTTP（有账号凭据时启用）

| 端点 | 鉴权 | 用途 |
|---|---|---|
| `GET https://zcode.z.ai/api/v1/zcode-plan/billing/balance?app_version=…` | Bearer zcode JWT | Start Plan 余额（plans + balances） |
| `GET https://bigmodel.cn/api/monitor/usage/quota/limit` | Authorization 头 API key 原样（无 Bearer） | Coding Plan 限额（limits[]） |

- 请求头带附录 A.3 全套（`X-Device-Mid` 取账号 virtualDeviceMid）
- token 经 `QuotaTokenProvider` 抽象注入（解耦账号域）；无 token 自动降级仅通路 A

## 3. PlanSlot 归一化契约（两源统一输出）

```
QuotaOverview { plans: [PlanSlot], refreshedAt, source }
PlanSlot { tier: Max|Pro|Lite|Start|体验|其他, tierCode, name, expire,
           total, used, remaining, percentUsed, items: [窗口/模型余额行] }
```

- tier 判定：plan_id+name 含 `max/pro/lite/start` → 对应档；含 `trial/taste/gift/weekend/promo/activity/体验` → 体验；槽优先级 max>pro>lite>start>trial
- balances 按 plan_id 挂槽；无 plan_id 且仅 1 槽挂唯一槽；孤儿余额进「其他额度」槽
- total/used/remaining 三者互推补全；`remaining_units` 为准（`available_units` 别名）
- quota/limit 的 `unit` 语义：3=每 N 小时（N=number，默认 5）、4=每天、5=每月、6=每周；`TIME_LIMIT` 优先作主指标；`nextResetTime`(ms) 本地化展示

## 4. 套餐重置卡

- 状态/使用走宿主 RPC（探针确认方法名 `useCodingPlanReset` / `getCodingPlanUsageSnapshot`；no-method 时 UI 隐藏区块）
- 使用带 `idempotency_key`（uuid）；限流业务码 3301 用 `next_try_at` 倒计时
- 5 小时卡/周卡分开计数；使用前确认弹窗

## 5. 福利中心（rewards）

- URL：`https://zcode.z.ai/cn/rewards?embedded=app&theme=zai-dark|zai-light`（theme 跟随 App 主题）
- 供票：加载前注入 localStorage 五键（同账号域 §4，注入脚本共用）
- origin 白名单：仅 zcode.z.ai 域内导航；外域链接交 url_launcher 或拦截
- **不注入** EventObserver/RPC hook（福利页独立，不参与会话观察）
- 注入脚本受 M0 铁律约束（禁 `//`、`/*`，语法测试守护）
