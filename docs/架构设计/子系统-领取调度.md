# 子系统-领取调度

> 行为域 source of truth（V2.0，2026-11-15 随 V2 计划建立）。代码行为变更须同批更新本文。
> 关联计划：[20261115-0901-V2大版本全面升级-开发计划](../开发计划/20261115-0901-V2大版本全面升级-开发计划.md) P2
> 常量移植源：zcode-switch v1.7.1 `src/main.js` 自动领取状态机

## 1. 职责边界

活动权益的自动检测与领取调度（默认关闭）、领取历史持久化、与手动领取的互斥让位、结果通知。领取 RPC 本体（preview/claim/captcha）属既有 claim_page 链路，本域只做**调度与状态**。

## 2. 通路

**只走通路 A（宿主 RPC）**：`codingPlanSubscriptionService.getManualClaimPlanPreviews / getCaptchaConfig / claimManualPlan` + `zr-captcha.verify`（无感）。宿主自带鉴权与风控头。设备 sessionStatus ≠ live 时轮次不执行；设备移除/会话 dispose 停表。

通路 B（直连 HTTP 领取）为实验位：仅保留接口占位与灰度开关，默认关，本期不实现。

## 3. 状态机常量（与 zcode-switch 对齐，改动需评测轮询放大效应）

| 常量 | 值 | 语义 |
|---|---|---|
| 轮间隔 | 10 min ±20% jitter | 每设备独立计时 |
| 首轮延迟 | 2 min | 调度器启动后 |
| 单次 claim 等待 | 45 s | 结果超时按失败计 |
| 单轮连领上限 | 5 | 成功后重新 preview 继续，达 5 停本轮 |
| 手动让位等待 | ≤90 s | 手动操作请求自动轮退出 |
| 手动结束冷却 | 60 s | 手动操作后自动轮的静默期 |

## 4. 冷却策略（业务码驱动）

| 情形 | 冷却 |
|---|---|
| code 1005（今日名额尽） | 服务端 `data.plan.ends_at` 精确时间 |
| 其他业务码（≥1000） | 1 h |
| 验证码需人工（无感失败） | 1 h + 通知提示（后台不弹交互框） |
| 其他失败（网络/超时） | 10 min |

**红线：无 `captchaVerifyParam` 不发 `claimManualPlan`（本地拒绝）**——宿主 claim 接口带阿里云验证头，缺失即 3007。

## 5. 静默时段与配置

- 默认 23:00–08:00 不触发（跨天区间）；可配置
- 配置存储：SharedPreferences `zremote.claimConfig.<deviceId>`（enabled 默认 false / silentStart / silentEnd）
- 开关关闭 = 零轮次零 RPC（反向验证测试保证）

## 6. 历史与反馈

- `ClaimRecord{时间, planId, planName, 结果码, 结果文案, 来源 auto|manual, 权益摘要}` → SharedPreferences `zremote.claim.<deviceId>` 快照，**非空才落盘**（清空不抹快照，参照 automation 模式）
- 成功/需人工 → 系统通知（新类型 claimResult）；工具箱领取卡徽标「今日已领 N」
- 离线可见最后快照 + 最后同步时间
