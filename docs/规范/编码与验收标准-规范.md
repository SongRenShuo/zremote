# code-standards（编码与验收标准）

> 本文件的条目来源分两类：**S 条目**——从 [`../LESSONS.md`](../LESSONS.md) 里 Seen 满 3 个不同日期的复发教训整体升级（不直接立新规）；**M 条目**——整节机制导入（须标注来源与引入日期）。格式两列：左列一句话祈使句规则，右列「审查者/复核者具体看什么」。审查定向测试报告、复核收口读数、评审他人提交时逐条对照；不满足的条目要在报告里点名说哪条不满足。

## 注入 JS 铁律（宿主 WebView 钩子脚本，M0 机制导入自 hook_script_syntax_test，2026-11-14）

| 规则 | 复核者看什么 |
|---|---|
| **M0-1 注入 JS 体内禁止 `//` 与 `/*` 两种注释序列（`://` 除外）** | 改 `lib/services/event_observer.dart` 的脚本后：①跑 `flutter test test/hook_script_syntax_test.dart`（零 `//` / 零 `/*` / 括号配平三判据）；②解释性注释一律写在 Dart 侧（`hookScriptFor` 的 doc 或常量旁）。证据：铁律由 syntax test 强制；2026-11-14 P1 改造曾用 `//` 与 `/*` 各踩一次（CI run #4 / #5 各抓一回）。 |
| **M0-2 注入 JS 语义改动必须双测试同批** | `test/hook_script.test.mjs`（node vm 语义场景）与 `hook_script_syntax_test.dart` 同批跑；语义测试用 `Process.run('node')` 驱动，本机无 node 时该测试静默跳过——**跳过 ≠ 通过**，本机必须实际跑过 `node test/hook_script.test.mjs` 再报读数。 |
| **M0-3 服务发现策略改动必须带新语义场景** | 改 `zrFindServices`/别名/缓存逻辑时，`hook_script.test.mjs` 里必须新增对应场景（放宽判定、window 回退、退避、失效重找各有既有先例可抄）；只改实现不改场景的提交打回。 |

## Tests 与验证

| 规则 | 复核者看什么 |
|---|---|
| **M1 脚本化测试桥的行为变更必须加开关，不许静默改写既有语义** | 改 `test/scripted_bridge.dart` 默认行为（如耗尽回空）时：新增具名参数（如 `respondEmptyOnExhausted`）默认值保持旧语义不变，或逐个用例审读影响面；依赖「沉默 → 超时」的用例显式关掉（2026-11-14 先例：`service_probe_test` 两处）。 |
| **M2 RPC 命令序列类测试按候选数重算** | 改 rpc_bridge 服务别名/重试策略后，所有按 `dispatch.commands` 索引断言的测试必须按「每频道候选数 × 重试次数」重算 errors 映射与 hasLength（2026-11-14 实测：23 个测试连坐）；`flutter test` 全量跑过才算收口，定向过不算。 |
| **M3 同 testWidgets 二次 pumpWidget 同类型 widget 走 didUpdateWidget 复用 State** | 需要页面「重新初始化」（重跑 initState/换 bridge）的场景必须拆独立 testWidgets，不能用第二次 pumpPage 实现（initState 不会重跑、`_loadError` 等状态沿用）；复核时看测试是否有「二次 pump 同类型」模式。 |
| **M4 横幅/浮层里的动作按钮用 Key 定位** | IndexedStack/离stage 里有同名文本时，`find.text(...).first` 可能点到隐藏元素（tap 静默无效）；给可见动作加 `Key('xxx-retry')` 这类具名键并用 `find.byKey`；AnimatedSize 包裹的横幅先 `pumpAndSettle` 再点。 |
| **M5 解析层fromJson 禁止「全空即 null」一刀切** | 新模型/改模型：字段缺失时区分「形似该对象（有关键键）→ 降级渲染」与「完全不像 → null 报错」；降级条件写反会导致页面整页报错（2026-11-14 ProviderSettingsView 实例，CI 实测抓到）。 |
| **S2 反向验证必须成对且有对照，空绿不算数**（机制导入自插件仓） | 修复/守卫类改动：摘掉修复分支必须变红；解析容错类改动用「形状漂移 fixture」当反例（外壳包裹、字段缺失、类型漂移三类，见 `usage_stats_test` / `provider_settings_test` 先例）。 |
| **S3 定向测试以判据数收读数** | `--plain-name` 不匹配会静默 0 例且全绿——报告必须给用例数；`flutter test` 全量（本机 ~665 例）在收口前至少跑一次全量，定向过不算全量。 |
| **S4 收口多步禁用 `&&` 串联** | 多步收口（构建 → 安装 → 启动 → 验证）分步检查退出码；`flutter run` 失败会伪装成「进行中」（后台任务不退出才是活着）。 |
| **S6 证据看产物，不看文档自述** | 判断「跑起来了」以 adb 读数为准：`adb shell pidof cn.song.zremote` 非空 + logcat 渲染日志；CI 以 GitHub Actions 结论为准；「未复现」如实标注 not run。 |
| **S7 修 bug 必 grep 同型兄弟** | 修一处解析容错/空判/别名时，grep 同模式调用点一并修（2026-11-14 先例：`ProviderSettingsView.fromJson(r.firstObject...)` 五处同型一次替换）。 |

## 本机环境红线（Windows + Flutter，2026-11-14 全链路实测）

| 规则 | 复核者看什么 |
|---|---|
| **E1 Gradle 发行包禁直连官网** | `services.gradle.org` 直连 30KB/s 且 Premature EOF 断流；用腾讯镜像 `https://mirrors.cloud.tencent.com/gradle/` 预置到 `~/.gradle/wrapper/dists/gradle-<版本>-<类型>/<hash>/`（hash 目录由首次失败构建自动生成，zip 落位即跳过下载）。实测 30KB/s → 3.8MB/s。 |
| **E2 Gradle 必须用 JDK 21，禁用 Studio JBR 与系统 JDK 1.8** | Studio JBR 是 Java 25，Kotlin `JavaVersion.parse` 直接抛 `IllegalArgumentException: 25.0.4`；系统 JDK 1.8 又太老。`android/gradle.properties` 的 `org.gradle.java.home=D:/HuanJing/Java/jdk-21.0.2` 是**本机路径，勿提交**；换机器先重审此行。 |
| **E3 国内依赖源优先级** | Gradle 发行包：腾讯镜像；JDK：华为镜像 `mirrors.huaweicloud.com/openjdk`；Android SDK 组件（NDK/CMake/system-images）：dl.google.com 直连通常快，勿挂代理；Google CDN 经代理实测 2.5MB/s、edgedl.me.gvt1.com 经代理 ~880KB/s。 |
| **E4 SDK 组件自动安装可能解压损坏** | Gradle 报 `InstallFailedException: Failed to install SDK components` 且 `.temp` 目录有半截 unzip → 删 `Sdk/.temp` 后用 `sdkmanager "<组件>"` 正式安装（cmdline-tools 在 `Sdk/cmdline-tools/latest`，JAVA_HOME 用 JBR 可跑 sdkmanager，但 Gradle 构建仍走 E2 的 JDK 21）。 |
| **E5 flutter run 卡 "Installing" 的解法** | 安装完成但启动握手慢/挂起时：手动 `adb shell am start -n cn.song.zremote/.MainActivity` 拉起，flutter 会话会自动附着（端口转发 + VM service）；确认附着看日志三件：`Syncing files`、`Flutter run key commands`、`A Dart VM Service ... is available`。 |
| **E6 诊断三板斧顺序** | 构建失败先看「What went wrong 的异常消息本体」（裸版本号=NDK/Java 兼容问题；InstallFailedException=SDK 组件损坏）→ 再 `--stacktrace` 找 `Caused by` 首条 → 环境类问题查 `.gradle/wrapper/dists`、`Sdk/.temp`、`build/` 三个缓存目录。 |

## 提交与文档

| 规则 | 复核者看什么 |
|---|---|
| **S8 提交信息走文件 `-F` 或纯 ASCII 行内，body 带验证记录** | 禁 `git commit -m` 内联反引号/中文长文（Git Bash 命令替换与乱码陷阱）；授权提交的 body 写「跑了什么测试、读数多少」；本仓现行中文行内提交风格可保持，但**长 body 一律写文件 `-F`**。 |
| **S9 文档契约与代码同源** | 行为域文档（`docs/架构设计/子系统-*.md`）改契约须同批更新；一个事实只写一处、他处链接；本机路径类事实归 `本机环境清单-规范.md`，别散落各文档。 |
| **S10 本机工具红线**（机制导入自插件仓） | Git Bash 传 `/X` 参数一律 `.ps1` 化；robocopy 0~7 均成功；跨调用写文件用 Edit/Write 工具；Windows 长路径删不掉用 `\\?\` 前缀 + `rd /s /q` 写成 `.ps1` 执行。 |
| **S11 推送前本地全量验证** | push 前本地 `flutter test` 全量 + `flutter analyze` 零问题（2026-11-14 教训：analyze 一个 unused_import 就能让 CI 红）；推送后 CI 结果后台确认，用户不要求时不盯盘。 |
