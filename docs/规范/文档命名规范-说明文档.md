# 文档命名规范-说明文档

> docs 目录的职责划分、命名规则与索引方式。机制引自 mybatis-plus-sql-visualizer 仓库（2026-11-14），按本仓体量裁剪。

## 目录职责总览

| 目录 | 职责 | 命名 |
|---|---|---|
| `docs/规范/` | 长期有效的规则与标准（编码验收、命名、本机环境清单） | `{主题}-规范.md` |
| `docs/LESSONS.md` | 教训账本（固定位置，不进子目录） | 固定名 |
| `docs/经验总结/` | 事件叙事与完整排查过程（时间线、误判、实测读数） | `{YYYYMMDD}-{HHMM}-{主题}-经验总结.md` |
| `docs/开发计划/` | 提案与实施计划（写"将要做什么"） | `{YYYYMMDD}-{HHMM}-{主题}-开发计划.md` |
| `docs/架构设计/` | 行为域文档：子系统职责与契约的 source of truth | `子系统-{名称}.md` |
| `docs/验收文档/` | 一次交付的集中验收材料（操作路径+预期结果） | `{YYYYMMDD}-{HHMM}-{主题}-验收文档.md` |
| `docs/索引/` | 开发计划等条目的索引 | `开发计划.md` |
| `docs/` 根 | 跨生命周期仍被引用的既有文档保留原位（见"历史文件"节） | — |

## 命名通用规则

1. 日期 `YYYYMMDD` + 时分 `HHMM`（取**创建时刻**）。
2. 主题用简短中文，一个文档只讲一件事。
3. `README.md` 引用的对外文档可豁免日期前缀（如既有 `dev-plan-toolbox-fix.md` 保留原位；新建文档一律带日期）。
4. **一个事实只写一处**：他处链接不复制；时间线叙事归经验总结，可执行规则归 LESSONS，长期标准归规范。

## 维护规则

- 新增文档落对目录、按规范命名，并在 `docs/索引/开发计划.md`（计划类）登记一行。
- 经验总结**只增不改**（历史叙事不可回写）；LESSONS 只记可执行规则；规范文件可修订（顶部注明修订日期）。
- 文档写现状：代码行为变了，归属文档同批更新，否则该文档失效。
