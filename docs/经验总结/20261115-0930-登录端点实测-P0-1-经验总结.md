# 登录端点实测（P0-1）：chat.z.ai / bigmodel.cn 直连可用性与验证码要求

## 1. 可达性

| 域名 | 直连结果 |
|---|---|
| `https://chat.z.ai` | 200 |
| `https://bigmodel.cn` | 200 |
| `https://zcode.z.ai` | 307（正常，根路径重定向） |

三家域名国内直连全部可达，**无 IP 层拦截**——z.ai「国内只显示手机号」确认是登录页渲染分流，不影响 API 直连。

## 2. chat.z.ai（zai / zai_cn 入口）

- `POST /api/v1/auths/signin`（email+password）：`{"detail":"The captcha verification failed."}`
- `POST /api/v1/auths/phone/send-code`（phone）：同上
- **结论：登录接口强制 `captcha_verify_param`（阿里云滑块）**，缺失即拒。接口本身可达、无账号锁定迹象（错误是验证码层，未触达账号校验）。

## 3. bigmodel.cn（BigModel 入口）

从 `https://bigmodel.cn/login` 页面 bundle 静态还原（webpack chunk id 6966 = login 壳；表单组件在主 chunk 20.js；静态资源 `static.bigmodel.cn/wd-paas-front/js/`）：

- **登录 API：`POST https://bigmodel.cn/api/auth/login`**（axios baseURL `/api`，请求头 Origin/Referer 需带 bigmodel.cn）
- payload 形状（三 Tab：`sms`=验证码 / `password`=账号密码 / `email`=邮箱）：

```json
{
  "phoneNumber": "", "countryCode": "86",
  "username": "<手机号/用户名/邮箱>",
  "smsCode": "", "password": "<密码>",
  "loginType": "password",
  "grantType": "customer", "userType": "PERSONAL", "userCode": ""
}
```

（bxy 特例 `loginType:"bxy"`；邮箱 Tab 带 `email/emailCode/consentType/consentTime`；微信 Tab `loginType:"wechat_open"` 带 openId/unionId）

- 实测演进：缺 loginType → `{"msg":"错误的登录类型","code":500}`；形状正确后 → `{"msg":"请完成安全验证","code":500}`
- 验证码是**数美（Shumei）**：`shumeiVisible`、`captchaInstance`、rid 存 localStorage `captcha_rid`（`CaptchaRidKey` 常量），登录表单内嵌 `CaptchaComponent`（`pwdCaptchaRef` verify-success 后才提交）
- **结论：强制数美 rid，原生 API 账密登录不可行。**

## 4. 对 P0-2/P0-3 的设计裁定（本实测的目的）

| 原计划 | 裁定 |
|---|---|
| 原生 API 账密登录（signin/auth/login 直调） | **放弃**——两家都强制人机验证参数，SDK 级集成（数美/阿里云原生滑块）工程量大且脆弱，违反「验证码联动走现有无感通道」的前提（`zr-captcha` 是宿主页场景，登录时宿主未登录不可用） |
| WebView 内嵌官方登录页 | **升为主方案**——新增 `LoginWebPage`（内嵌 WebView 全屏页）：provider 选择（BigModel / Z.ai）→ 加载 `bigmodel.cn/login?redirect=<oauth回调>` 或 chat.z.ai 授权页 → 用户在**真实官方登录页**完成账密/手机号/微信登录（浏览器同款体验）→ 检测登录完成 → 自动走 OAuth 完成链（authorize → code/轮询 → token 交换）→ localStorage 五键注入供票 → 回会话页 |
| E2E 真实登录 | 滑块行为检测下 adb 自动化成功率存疑：E2E 时允许 ≤3 次尝试，失败即落待人工验证清单；供票链路由 zcode-switch CLI `.zsb` 兜底保证可验证 |

## 5. 收获的额外事实（供 L1/L2 车道使用）

- bigmodel 登录成功响应含 `access_token` + `expires_in`（分钟，默认 `DEFAULT_TOKEN_EXPIRES_MINUTES=10080`），存 localStorage `bigmodel_token_production`
- 组织/项目头：`Bigmodel-Organization` / `Bigmodel-Project`（localStorage `Organizations`/`ProjectMembers`）
- zcode.z.ai OAuth 完成链不受影响：`cli/init` / `poll` / `token` 端点无需验证码（验证码只在 chat.z.ai/bigmodel.cn 登录层）
