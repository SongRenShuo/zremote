# 经验总结：鸿蒙（HarmonyOS NEXT）支持立项

> 2026-11-16。计划册：[20261116-1434-鸿蒙NEXT全面支持-开发计划](../开发计划/20261116-1434-鸿蒙NEXT全面支持-开发计划.md)。
> 提交：`3691207`（P0/P1/P4）、`b1afa3e`（P5）、`91e971c`+`07144f2`（P2）、`ab2bb13`/`40d1669`（文档/教训）。

## 1. 目标与裁定

用户诉求「全面支持鸿蒙」。裁定：目标是 **HarmonyOS NEXT（纯血鸿蒙）**——它移除了 AOSP，**不能装 APK**；HarmonyOS 4.x 仍是 AOSP 底座，可直接装现有 APK，非目标。方案走 **CPF-Flutter/flutter_flutter（Flutter-OH）SDK 分叉 + `ohos/` 工程**，复用 Dart 业务；否決 ArkTS 原生重写（109 个 Dart 文件、90 个测试文件双份维护不划算）。

## 2. 关键调研结论（带出处）

- Flutter-OH 最新稳定线基于 **Flutter 3.41.9**（本仓 3.38.5）；SDK 是**完整 Flutter 分叉**（`git clone` + `bin/flutter`），`flutter build hap` 出包。来源：`gitcode.com/CPF-Flutter/flutter_flutter`、`flutter_samples` 文档。
- 插件面**无硬阻塞**：inappwebview / mobile_scanner / secure_storage / local_auth / notifications / url_launcher / share_plus / path_provider / file_picker / device_info_plus / package_info_plus / shared_preferences **均有 CPF 适配**，但**多为 git fork（`-ohos-` tag，不在 pub.dev）**。
- HarmonyOS 有系统 Web（ArkWeb），`flutter_inappwebview_ohos` 封装；部分 API 不支持（`onCreateWindow`/`onDownloadStartRequest`/`keepAlive`/`windowId`）。
- 社区 CI action：`openharmony-rs/setup-ohos-sdk`（装 OpenHarmony SDK，导出 `OHOS_BASE_SDK_HOME`/`OHOS_SDK_NATIVE`）；无官方 turnkey Flutter-OH workflow。

## 4. 排雷（复发先查）

- **stock Flutter 无 `Platform.isOhos`、`TargetPlatform` 无 `ohos`**——直接写编译失败；新平台判定必须自建能力层（见 LESSONS L32）。
- **GitCode 页面不可抓取**（WebFetch 只回导航壳）；模板改用 **GitHub 镜像 `zhongdaiqi/flutter_flutter`** 的 `raw.githubusercontent.com` 取 `ohos.tmpl/`，可拿到逐字模板。
- **`openharmony-rs/setup-ohos-sdk` 导出的是 `OHOS_BASE_SDK_HOME`/`OHOS_SDK_NATIVE`，没有 `HOS_SDK_HOME`**——CI 里别写错变量。
- `dependency_overrides` **无平台条件**，一份 pubspec 服务三端时，插件 fork 替换会连带改 Android/iOS（见 LESSONS L33）。

## 5. 未验证 / 下一步

- 本机**未装** DevEco/OpenHarmony SDK 与设备：`flutter build hap`、签名、真机走查均 **not run**。
- P3 依赖迁移（inappwebview 本地 Android fork × CPF ohos fork）需工具链联调，是**最大不确定性**。
- CI ohos 腿的工具链安装方式（尤其 `flutter config --ohos-sdk` 期望的 SDK home 形态）首跑校准。
