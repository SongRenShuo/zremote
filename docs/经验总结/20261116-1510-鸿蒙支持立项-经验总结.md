# 经验总结：鸿蒙（HarmonyOS NEXT）支持立项

> 2026-11-16。计划册：[20261116-1434-鸿蒙NEXT全面支持-开发计划](../开发计划/20261116-1434-鸿蒙NEXT全面支持-开发计划.md)。
> 提交：`3691207`（P0/P1/P4）、`b1afa3e`（P5）、`91e971c`+`07144f2`（P2）、`ab2bb13`/`40d1669`（文档/教训）。

## 1. 目标与裁定

用户诉求「全面支持鸿蒙」。裁定：目标是 **HarmonyOS NEXT（纯血鸿蒙）**——它移除了 AOSP，**不能装 APK**；HarmonyOS 4.x 仍是 AOSP 底座，可直接装现有 APK，非目标。方案走 **CPF-Flutter/flutter_flutter（Flutter-OH）SDK 分叉 + `ohos/` 工程**，复用 Dart 业务；否決 ArkTS 原生重写（109 个 Dart 文件、90 个测试文件双份维护不划算）。

## 2. 关键调研结论（带出处）

- Flutter-OH 最新稳定线基于 **Flutter 3.41.9**（本仓 3.38.5）；SDK 是**完整 Flutter 分叉**（`git clone` + `bin/flutter`），`flutter build hap` 出包。来源：`gitcode.com/CPF-Flutter/flutter_flutter`、`flutter_samples` 文档。
- 插件面**无硬阻塞**：inappwebview / mobile_scanner / secure_storage / local_auth / notifications / url_launcher / share_plus / path_provider / file_picker / device_info_plus / package_info_plus / shared_preferences **均有 CPF 适配**，但**多为 git fork（`-ohos-` tag，不在 pub.dev）**。
- HarmonyOS 有系统 Web（ArkWeb），`flutter_inappwebview_ohos` 封装；部分 API 不支持（`onCreateWindow`/`onDownloadStartRequest`/`keepAlive`/`windowId`）。
- 社区 CI action：`openharmony-rs/setup-ohos-sdk`（装 OpenHarmony SDK，导出 `OHOS_BASE_SDK_HOME`/`OHOS_SDK_NATIVE`）；无官方 turnkey Flutter-OH workflow。公开可跑样例 `niuhuan/harmony-next-flutter-pipeline-docker`（容器镜像，SDK 6.0.2.642 + Flutter 3.35.7-ohos，**无 3.41 镜像**）。
- 平台判定实测：`Platform.operatingSystem == 'ohos'`、`defaultTargetPlatform == TargetPlatform.ohos`；`Platform.isOhos` 存在但 **CPF FAQ 不建议用**（服务端引擎产物下 `run/build hap/attach` 会失败）。
- 插件 3.41 tag **未文档化**（CPF 表只到 3.35）；框架 tag 用 `3.41.10-ohos-1.0.1`。

## 4. 排雷（复发先查）

- **stock Flutter 无 `Platform.isOhos`、`TargetPlatform` 无 `ohos`**——直接写编译失败；新平台判定必须自建能力层（见 LESSONS L32）。
- **GitCode 页面不可抓取**（WebFetch 只回导航壳）；模板改用 **GitHub 镜像 `zhongdaiqi/flutter_flutter`** 的 `raw.githubusercontent.com` 取 `ohos.tmpl/`，可拿到逐字模板。
- **`openharmony-rs/setup-ohos-sdk` 导出的是 `OHOS_BASE_SDK_HOME`/`OHOS_SDK_NATIVE`，没有 `HOS_SDK_HOME`**——CI 里别写错变量。
- `dependency_overrides` **无平台条件**，一份 pubspec 服务三端时，插件 fork 替换会连带改 Android/iOS（见 LESSONS L33）。

## 5. 本机工具链搭建与 hap 构建（2026-11-16 实测，已验证）

用户授权后在本机 `D:\HuanJing` 装齐工具链并**成功构建 hap**（`entry-default-unsigned.hap`，148MB）。排雷记录：

1. **Dart SDK 下载 zip 被代理 range 续传污染**：大小对（199119085）但中央目录损坏（`zipfile` 打不开）→ 删 `BITEE36.tmp` 完整重下、手动解压、写 `engine-dart-sdk.stamp`。
2. **镜像变量踩坑**：`FLUTTER_STORAGE_BASE_URL` 设成 OH 镜像会让 stock `engine_stamp.json` 404 → 改用 `https://storage.flutter-io.cn`；OH 引擎产物走分叉默认 `FLUTTER_OHOS_STORAGE_BASE_URL`。
3. **SDK 目录布局**：Flutter-OH 的 `HmosSdk` 要求 `sdk/<子目录>/openharmony/toolchains/hdc.exe`；`flutter config --ohos-sdk` 指向 `command-line-tools/sdk`（不是 `sdk/default/openharmony`）。裸 OH SDK 用 `<root>/<数字API>/toolchains`。
4. **必须有完整命令行工具**（ohpm + hvigorw + SDK，2.6GB），裸 OpenHarmony SDK 缺 ohpm/hvigorw 无法构建。
5. **Git Bash 调 `.bat` 有 `BATCH RECURSION` 栈溢出** → 用 PowerShell 执行构建 bat。
6. **schema 错误两处**：`pathPrefix` 非法（正确 `pathStartWith`）；`ohos.permission.FOREGROUND_SERVICE` 在旧 SDK 未预定义（移除，保活通道本就未实现）。
7. **CPF 3.41 嵌入层 bug**：`OhosAutoFillHelper.ets` 引用公开 SDK 未导出的 `autoFillManager.AutoFillType/ViewData/...`（15 个 ArkTS 错误，所有公开 SDK API 12/23/24 都没有）→ `tool/patch_ohos_autofill.py` 降级为 `any`（Autofill 在 api<26 运行时短路）；每次 pub get/build 前必跑（oh_modules 生成物会被覆盖）。
