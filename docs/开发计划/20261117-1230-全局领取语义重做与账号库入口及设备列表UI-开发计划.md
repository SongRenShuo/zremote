# 开发计划：全局领取语义重做（单层总闸）+ 账号库入口扩展 + 设备列表 UI 优化

> 版本基准：main（探查时 HEAD `1ebbd2c`，已发布 v2.1.1）
> 目标：三项用户可感改动——①把双层开关重做为**单层全局总开关**（一键开关所有设备，后台新加设备默认继承，设备内单独改过则以设备为准）；②「接入新设备」弹框末尾补「从账户添加设备」入口（有设备后也可达）；③设备列表名称不再折叠看不全，并把误导性的「V2 账号」徽标改为**真实版本号**。
> 状态：已立项待实施
> 关联调研：只读探查（2026-11-17 子智能体，结论已并入 §2/§3/§4）；用户裁定（2026-11-17）：全局开关「单独设置优先」、V2 徽标「显示真实版本号」。
> 关联：`20261117-0024`（当前双层总闸实现，本轮重做其语义）；LESSONS L27（账户能力 0 设备可达）。

## 2. R1 全局领取：现状与重做方案

### 2.1 现状（双层乘法门控，证据）

- 全局总闸 `zremote.claimGlobal`（`lib/services/device_store.dart:329,356-374`），provider `claimGlobalEnabledProvider`（`lib/state/claim_config.dart:48-81`）；agent `_globalEnabled` 门控 start/runNow（`lib/services/claim_scheduler.dart:544-589`）；hub `setGlobalEnabled` 广播（`:65-70`）。
- 设备级开关 `ClaimAutoConfig.enabled`（默认 **false**，`claim_scheduler.dart:103`），键 `zremote.claimConfig.<id>`（`device_store.dart:327,333-354`）。
- 实际运行 = 全局 && 设备，两层独立 → 用户所见「两层开关」。

### 2.2 目标语义（用户裁定：单独设置优先）

**取消全局门控层，总开关变为「批量设置每台设备」的快捷操作**：

1. `ClaimAutoConfig` 增加字段 `locallyOverridden`（默认 false，JSON 键 `locallyOverridden`，M5 容错）：表示"用户在该设备领取页单独改过开关"。
   - 设备页 `claimConfig.setEnabled(id, value)` 置 `locallyOverridden: true`（**仅 enabled 变更打标**；`setSilent` 不打标）。
2. 全局开关写入改为**遍历所有设备批量落盘**：
   - `ClaimGlobalEnabledNotifier.setEnabled(v)`：读 `deviceListProvider` 全部设备 → 对每个 `claimAutoConfig(id)`，**仅当 `locallyOverridden == false`** 时写 `enabled = v`；同时把总开关值本身持久化（作为"新设备默认值"）。
   - agent/hub 的 `_globalEnabled` 门控、settings 页的 `ref.listen → setGlobalEnabled` 广播、领取页的 `claimGlobalOffHint` 与「全局关时不渲染立即执行」分支——**全部移除**（不再是运行期门控）。
3. **后台新增设备自动继承**：所有新增设备的唯一漏斗 `DeviceListNotifier.add()`（`lib/state/session_pool.dart:21-24`）/ `DeviceStore.add()`（`:55-65`）处，为新 id 写入 `ClaimAutoConfig(enabled: 当前全局默认值)`（locallyOverridden=false）。覆盖登录导入、账号库添加、深链、扫码/粘贴全部路径。
4. 设备页 `_autoCard` 的 Switch 保持（写 `setEnabled` 即打独立标记）；设置页 tile 文案改为「一键开启/关闭所有设备的自动领取（单独设置过的设备除外）」。

**兼容与边界**：
- 升级迁移：旧数据无 `locallyOverridden` 键 → 解析为 false（跟随总闸）；旧的 `zremote.claimGlobal=false` 语义变为「当前默认值关」+ 已有设备批量关（升级后首次进入设置页时按存储值执行一次批量同步，或采用惰性：仅影响新设备——见 §5 待定项，计划推荐前者）。
- 总开关读态：设置页 tile 的开关状态 = 存储的"全局默认值"（`zremote.claimGlobal`），不再反映每台设备的实际启停（因为可能有独立覆盖）。副文案补充「N 台独立设置」。

### 2.3 待删除/改造的既有代码清单

| 文件 | 改动 |
|---|---|
| `lib/services/claim_scheduler.dart` | `ClaimAutoConfig` 加 `locallyOverridden` + JSON/equality/hashCode；删除 agent `_globalEnabled`/`setGlobalEnabled` 及 3 处门控 |
| `lib/state/claim_config.dart` | `ClaimGlobalEnabledNotifier.setEnabled` 改批量写入（注入 DeviceListNotifier/DeviceStore）；`ClaimConfigNotifier.setEnabled` 打标 |
| `lib/state/claim_scheduler_hub.dart` | 删除 `build()` 的 `ref.listen(claimGlobalEnabledProvider)`、`setGlobalEnabled` 方法、attach 中的 `claimGlobalEnabled()` 读盘落位 |
| `lib/state/session_pool.dart` / `lib/services/device_store.dart` | `add()` 时写新设备默认领取配置（继承全局值） |
| `lib/ui/settings_page.dart` | `_ClaimAutoTile` 去读盘广播逻辑（保留读盘显示默认态）+ 新文案 |

## 4. R3 设备列表 UI 与版本号

### 4.1 名称折叠根因与改法（证据 `lib/ui/manage_page.dart:1209-1255`）

根因：`Flexible + maxLines:1 + ellipsis`（:1213-1217）被同行 V2 徽标（:1226-1229）、状态胶囊（:1231-1235）、待审批/今日已领徽章（:1237-1254）挤占宽度。

改法（名称完整可见，徽标让位）：
- 头部行改为**两行布局**：第一行名称独占整行（`Expanded` + `maxLines:2` + `ellipsis`，足够长名字两行显示全），第二行放版本号徽标 + 状态胶囊 + 可选徽章（`Wrap` 或 `Row` 可换行）。
- 或更保守：名称仍单行但移出 overcrowded Row 独立成行，徽标整体下移到指标行上方。
- 宽屏导轨 `app_shell.dart:428-443` 同样 `maxLines:1 + ellipsis`，一并改 `maxLines:2`（保持双栏布局观感）。
- 回归：`test/l4_widgets_test.dart:288-348`（find.text 定位、置顶坐标）、`test/rename_dialog_test.dart`（名称断言）——widget 树变化后 `find.text` 仍可命中文本即可。

### 4.2 V2 徽标 → 真实版本号（证据 `manage_page.dart:1226-1229`、`app_localizations_zh.dart:70`）

- 条件从 `device.kind == DeviceKind.v2` 改为：`device.params['app_version']` 非空即显示。
- 文案：`l10n.deviceVersionBadge(v)`（新 key，zh「v{version}」/en「v{version}」），或沿用 HwChip 显示 `v3.16.1`。无 `app_version` 的设备（部分 legacy 链接）不显示徽标。
- 真实值来源：`device.params['app_version']`（`link_builder.dart:12,30`、`remote_device_client.dart:402-403` 已写入）。
- `data_manage_page.dart:299-301` 同款徽标一并改（S7 grep 同型兄弟）。
- l10n：删除/弃用 `deviceV2Badge`（保留 key 避免其它引用断裂，但 UI 不再用），新增 `deviceVersionBadge`；`test/paste_import_test.dart:193`（`find.text('V2 账号')`）改为断言真实版本号（fixture 需带 `app_version`）。

## 6. 验收

- **R1 核心场景**：①总开关一键关 → 所有「未独立设置」的设备 enabled 落盘为 false，全部代理停表；一键开 → 恢复；②某设备在领取页单独切换后，总开关再切换不影响该设备（独立标记生效）；③后台通过账号库/登录/深链新增设备，默认 enabled 跟随当前总开关值；④设置页副文案显示"N 台独立设置"；⑤领取页不再有"全局已关闭"提示（该层移除）。
- **R2 核心场景**：有设备时，「接入新设备」弹框末尾出现「从账户添加设备」→ 点击打开 `AccountVaultPage`（device=null）→ 能完成添加并回到列表；0 设备原入口不回归。
- **R3 核心场景**：长名字设备卡两行内完整可见（不再被徽标挤成 `…`）；带 `app_version` 的设备显示 `vX.Y.Z` 而非「V2 账号」；无版本号设备不显示徽标；宽屏导轨同样不折叠。
- **反向验证（S2）**：摘掉 locallyOverridden 判断，独立覆盖用例变红；摘掉 add() 默认继承，新设备继承用例变红。
- **回归**：全量 `flutter test` + `flutter analyze` 零问题（S11）；上一轮 claim 定向用例随语义调整后照跑。
- **not run**：真机走查（纯 Dart/UI 层为主，无平台分支）。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| R1-1 升级迁移：旧 `claimGlobal=false` 用户期望批量关但惰性实现只影响新设备 | 计划推荐：升级后首次读取全局值时对存量设备执行一次批量同步（写 locallyOverridden=false 的设备）；用例锁升级路径 |
| R1-2 批量写遍历全部设备的并发/失败 | 串行写入 + 每设备 try/catch 不中断整批（zcode-switch 逐账号同款） |
| R1-3 删除全局门控后，正在运行的 agent 状态不同步 | 总开关批量写后逐设备 `hub.updateConfig()` 即时生效（内存中代理同步停/启） |
| R3-1 名称两行布局在极小屏仍溢出 | `maxLines:2 + ellipsis` 兜底；徽章 `Wrap` 可换行 |
| 共写 manage_page | 顺序实施，不并行 |
