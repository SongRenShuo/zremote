# 开发计划：无设备登录与账户设备导入（上游数据迁移路径）

> 版本基准：main（commit `3db62bc`；包名迁移 `20261115-2354` 实施中，与本计划写集不重叠）
> 目标：打通「装 fork → 登录 zcode 账号 → 一键拉取账号下设备」路径，消除**全新安装（0 设备）无法登录**的断点，让用户无需先扫码即可自助重建设备库。
> 状态：提案（只立项，暂不实施）
> 关联：数据迁移调研结论（2026-11-16，只读子智能体）；包名迁移计划（`20261115-2354`）。

---

## 1. 背景

数据迁移调研已定论：上游 `pjpv/zremote` 的用户数据**无法跨包搬移**（硬约束：签名不同、`flutter_secure_storage` 密钥绑定包名/UID、双方 `allowBackup=false`、上游无导出能力）。唯一可行路径是**重新登录 + 服务端设备列表 + 手动重设**。

但该路径在当前代码里**断在第一步**：登录入口只能从「设备会话页」进入，而全新安装时没有任何设备 → 无法登录 → 也就无法用服务端列表恢复设备。

---

## 2. 缺陷与根因（代码证据，2026-11-16 实测）

| # | 事实 | 证据 |
|---|---|---|
| 1 | `LoginWebPage` 构造**强制要求** `device` | `lib/ui/login_web_page.dart:149-152`（`required this.device`） |
| 2 | `AccountVaultPage` 构造**强制要求** `device` + 会话回调 | `lib/ui/account_vault_page.dart:27-38` |
| 3 | 登录唯一入口在设备会话页 | `lib/ui/session_view.dart:484` `_openLogin`；触发点 `:629`、`:1180` |
| 4 | 「从账户添加设备」依赖当前设备 | `account_vault_page.dart:137-146`（`activeAccountOf(widget.device)`） |
| 5 | 空设备态只有扫码/粘贴 | `lib/ui/manage_page.dart` 空态文案 `emptyTitle`「还没有接入设备」（`app_zh.arb:68-73`） |

**判定**：登录与账户设备导入都被「必须先有一个设备」的前置条件锁死。这不是迁移工具缺失，而是**入口可达性缺陷**。

---

## 3. 修复方向

| # | 任务 | 要点 |
|---|---|---|
| D1 | `LoginWebPage` 的 `device` 改为**可选** | 无设备时用默认/隔离 WebView profile 完成官方登录流；登录成功后进入「选择/添加设备」流程（而非必须 pop 回某设备会话） |
| D2 | 无设备可达的**登录入口** | 设备列表空态主按钮 / 设置页账号区 / 工具箱 任一处可达「登录账号」；与既有设备内登录复用同一 `LoginWebPage` |
| D3 | 账户设备导入**解绑 device** | 「从账户添加设备」改用全局活跃账号（或账号选择器）拉取 `RemoteDeviceClient.listDevices`（`remote_device_client.dart:236`），写 `deviceListProvider`；不依赖 `widget.device` |
| D4 | 登录后引导 | 登录成功且账号下有多设备时，引导进入 `AccountDevicePickerPage` 一键导入 |

## 5. 验收

- 0 设备时可进入登录并完成官方登录流；登录后可拉取账号设备列表并导入。
- 既有设备内登录/保险库流程不回归。
- 单测：无设备登录路径、账户设备导入不依赖 device、登录后引导。
- 全量 `flutter test` + `flutter analyze` 收口。

---

## 6. 风险

| 风险 | 缓解 |
|---|---|
| R1 登录 WebView profile 与设备绑定（多设备隔离语义） | 无设备时用默认 profile，登进设备后再走既有 profile 逻辑；保持隔离语义不变 |
| R2 全局活跃账号与 `activeAccountOf(device)` 语义冲突 | 明确「全局活跃账号」选取规则（最近使用/唯一账号），补测试 |
| R3 与包名迁移、2249 计划并发 | 写集不重叠；l10n 前缀隔离；合并顺序：包名迁移先收口 |
| R4 迁移仍需手动重设设置项 | 本计划只解决「登录+设备」；设置迁移另议（当前调研建议手动） |

---

## 7. 不在本轮（调研硬约束备忘）

- 上游数据**不能**搬移：签名不同 + secure storage 密钥绑定包名/UID（`KeyCipherImplementationRSAOAEP.java:41`）+ 双方 `allowBackup=false` + 上游无导出能力。
- 本计划是「重建路径」，不是「迁移工具」；`.zsb` 仅服务 fork 自身跨安装迁移。
