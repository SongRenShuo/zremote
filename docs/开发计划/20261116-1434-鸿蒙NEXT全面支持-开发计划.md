# 开发计划：鸿蒙（HarmonyOS NEXT）全面支持

> 版本基准：v2.0.3（commit `f227a37`，main）
> 状态：**已发布（2026-11-17，v2.1.1 四资产齐发：android 76.2MB / ios-unsigned 10.8MB / ohos-arm64 28.2MB / ohos-x64 30.5MB）**——模拟器首屏与核心链路走查通过（截图证据）。**发布签名线 2026-11-17 打通**：ECC 密钥 + 发布证书 + 发布 Profile → `flutter build app` 三件套 → 签名 `.app` → AGC 上传成功（L47/L48）；release.yml 已改为 CI 出签名 `.app`（待 tag 实跑核对）。真机走查仍为遗留（无真机）。（v2.1.0 曾因 hap 仅 arm64 导致模拟器装不上而下架）
> 触发：用户诉求「应用需要全面支持鸿蒙系统」（2026-11-16）
> 关联规范：[编码与验收标准](../规范/编码与验收标准-规范.md)、[本机环境清单](../规范/本机环境清单-规范.md)、[派活与验收清单](../开发流程-派活与验收清单.md)

## 1. 需求与目标

### 1.1 用户诉求

「现在应用需要全面支持鸿蒙系统」——让 ZRemoteX 能在鸿蒙设备上安装、登录、远控、领取、看额度，能力对齐 Android/iOS。

### 1.2 目标平台裁定

| 系统 | 是否本计划目标 | 理由 |
|---|---|---|
| **HarmonyOS NEXT（5.x，纯血鸿蒙）** | ✅ 目标 | 已移除 AOSP，**不能装 APK**；用户说的「全面支持鸿蒙」实质就是它 |
| HarmonyOS 4.x | ❌ 非目标 | 仍是 AOSP 底座，**可直接装现有 APK**，无需改造 |
| Android / iOS | 维持现状 | 不得回归 |

### 1.3 方案裁定：走 Flutter-OH 移植，不重写 ArkTS

- **选择**：采用社区 **CPF-Flutter/flutter_flutter**（OpenHarmony-SIG 后继）Flutter-OH SDK 分支，新增 `ohos/` 平台工程，复用全部 Dart 业务代码。
- **否决**：ArkTS/ArkUI 原生重写——109 个 Dart 文件、90 个测试文件、账号/领取/远控全部业务逻辑要重写并长期双份维护，收益不抵成本。
- **代价（如实写明）**：Flutter-OH 是**社区维护的 SDK 分叉**（非 Google/华为官方），最新稳定线基于 Flutter 3.41.9；本仓现为 Flutter 3.38.5。插件需换成 CPF-Flutter 的 **git 版 fork（`-ohos-` tag，多数不在 pub.dev）**。这是本计划最大的不确定性来源。

### 1.4 非目标（本期不做）

- 不接 AppGallery 上架（签名/软著/备案流程），本期只到「可签名 hap 构建 + 可侧载」。
- 不做鸿蒙原子化服务/元服务。
- 不改桌面端 ZCode 协议。

## 2. 现状与差距分析

### 2.1 平台工程现状

- 工程只声明 `android/` + `ios/`（`.metadata` migration.platforms 仅 root/ios；android 由 flutter 工具识别）。**无 `ohos/` 目录**，全仓 grep `ohos`/`harmony`/`鸿蒙` 零命中。
- `.flutter-plugins-dependencies` 平台分类只有 ios/android/macos/linux/windows/web，**无 ohos 分类**——即当前没有任何插件声明 ohos 实现。

### 2.2 手写原生通道（全部只有 Android 实现）

| 通道 | Dart 侧 | Android 原生 | ohos 侧现状 |
|---|---|---|---|
| `zremote/deeplink` | `lib/services/deep_link.dart:13` | `MainActivity.kt`（initial/onNewIntent） | 缺失（缺省会静默降级，深链导入失效） |
| `zremote/keepalive` | `lib/services/keepalive.dart:13` | `MainActivity.kt` + `KeepAliveService.kt` | 缺失（保活失效） |
| `zremote/app` | `lib/services/app_settings.dart:4` | `MainActivity.kt`（openAppSettings） | 缺失（跳转应用设置失效） |

> Dart 侧普遍 `catch MissingPluginException` 降级，所以「缺失不崩」，但功能静默丢失——必须在 ohos 补齐或明确标注不支持。

### 2.3 插件支持面（CPF-Flutter 适配清单，2026-11 调研）

| 插件 | ohos 适配 | 备注 |
|---|---|---|
| flutter_inappwebview | ✅ 有（`flutter_inappwebview_ohos`） | 部分 API 不支持（`onCreateWindow`/`onDownloadStartRequest`/`keepAlive`/`windowId` 等） |
| mobile_scanner | ✅ 有 | 需 `ohos.permission.CAMERA` |
| flutter_secure_storage | ✅ 有 | 需 `ohos.permission` 无关；用 CryptoArchitectureKit |
| local_auth | ✅ 有 | 需 `ohos.permission.ACCESS_BIOMETRIC` |
| flutter_local_notifications | ✅ 有 | 需通知权限 |
| url_launcher / share_plus / path_provider / file_picker / device_info_plus / package_info_plus / shared_preferences | ✅ 有 | 均为 git fork |
| flutter_riverpod / uuid / intl / dio / cryptography | ✅ 纯 Dart 或已适配 | cryptography 有 fluttertpc 适配 |

**结论**：插件面没有硬阻塞；主要工作量在「git fork 依赖替换 + 平台分支 + 原生通道重写 + CI」。

### 2.4 平台分支点（Dart）

| 位置 | 现状 | 需改 |
|---|---|---|
| `lib/services/zai_auth_client.dart:218-227` | `Platform.isAndroid` / `isIOS` 二分，其余落 unknown | 补 ohos 分支（platform/osCategory/osVersion） |
| `lib/services/quota_client.dart:1089,1093` | `defaultTargetPlatform == iOS ? ... : android` | 补 ohos 分支 |
| `lib/services/webview_profile.dart:32-33` | iOS→true，非 android→false | 补 ohos 分支（MULTI_PROFILE 语义） |
| `lib/ui/ios_limits_section.dart:29` | `Platform.isIOS` | 通用化为「平台限制说明」（iOS + 鸿蒙各自条目） |
| `lib/ui/account_vault_page.dart:297` | `Platform.pathSeparator` | 与 ohos 无关（dart:io 通用），保持 |

> ⚠️ `Platform.isOhos` / `TargetPlatform.ohos` 在** stock Flutter 3.38.5 不存在**，直接写会编译失败。必须建立自己的能力抽象（P1），不能用 stock API 假设。

### 2.5 CI 现状

- `ci.yml`：`check`（analyze + test，ubuntu）+ `ios`（build ios，macos）；触发 = push main / PR / workflow_dispatch。
- `release.yml`：`verify` + `apk` + `ipa` → `publish`（tag 触发），资产名 `ZRemoteX-v<版本>-android.apk` / `-ios-unsigned.ipa`。
- **无 Android APK 构建腿在 ci.yml**，也**没有任何 ohos 构建**。

## 3. 分阶段实施

### P0 方案裁定与需求边界（本文件）
- 写集：本文件、索引。
- 验收：方案裁定明确、目标/非目标清晰、风险如实。

### P1 平台能力抽象层（可本地全量验证）
- **目标**：建立 `lib/services/platform_caps.dart`，统一回答「是不是 ohos / 是不是 iOS / 是不是 Android」，供所有平台分支使用；**不依赖 stock Flutter 不存在的 API**。
- **写集**：`lib/services/platform_caps.dart`（新增）、`zai_auth_client.dart`、`quota_client.dart`、`webview_profile.dart`、`ios_limits_section.dart`（改名/扩展为 `platform_limits_section.dart`）、`pubspec.yaml`（若需）、`test/platform_caps_test.dart`（新增）+ 相关既有测试。
- **关键设计**：
  - 用 `Platform.operatingSystem`（String，stock 可用）+ 编译期/运行期探针判定 ohos；提供 `PlatformCaps.ohos` 常量与可注入覆盖（`PlatformCaps.debugOverride`），供测试与 OH 分叉升级期兜底。
  - 平台分支一律改为查 `PlatformCaps`，禁止再散写 `Platform.isAndroid`。
  - 若 OH 分叉后续提供 `Platform.isOhos`，再收敛为单一来源（本文件留 `TODO(OH)`）。
- **验收**：新增定向用例；`flutter analyze` 零问题；全量 `flutter test` 绿；Android/iOS 行为不回归。

### P2 ohos 平台工程脚手架（无本地工具链，标注 not run）
- **目标**：新增 `ohos/` 目录，使 CPF-Flutter SDK 能识别并构建。
- **写集**：`ohos/**`（AppScope/app.json5、build-profile.json5、hvigorfile.ts、oh-package.json5、entry/src/main/ets/entryability/EntryAbility.ets、pages/Index.ets、plugins/GeneratedPluginRegistrant.ets、module.json5、resources）、`ohos/README.md`（本机工具链搭建与构建步骤）。
- **内容**：
  - `bundleName` 暂定 `cn.song.zremote`（与 Android/iOS 一致，避免账号/深链 bound 冲突）；
  - 权限：INTERNET、CAMERA、BIOMETRIC、通知、前台服务（`ohos.permission.FOREGROUND_SERVICE*`）；
  - 深链：`zrsong://import` 与 `https://zcode.z.ai/remote`（module.json5 `skills`/`uris`）；
  - 原生通道 ohos 实现：`zremote/deeplink`（Want 参数）、`zremote/keepalive`（前台服务/长时任务）、`zremote/app`（跳设置）；
  - 签名：`signingConfigs` 占位，CI 用 secrets 注入。
- **验收**：CPF-Flutter SDK 下 `flutter create --platforms ohos` 对齐目录结构；`flutter build hap --debug` 通过（**需本机装 DevEco/ohos SDK，当前未装 → not run**）。

### P3 依赖迁移策略（需工具链联调）
- **目标**：让同一份 `pubspec.yaml` 同时服务 Android/iOS（现状）与 ohos（fork 插件）。
- **候选策略**（择一，联调时定）：
  - **S1（首选）**：`dependency_overrides` 指向 CPF-Flutter git fork；**保留** `third_party/flutter_inappwebview_android` + `platform_interface` 覆盖以守住 Android 的 MULTI_PROFILE；新增 `flutter_inappwebview_ohos`。
  - **S2**：全量换 CPF fork，把 MULTI_PROFILE 需求回灌到 CPF fork 或改为 ohos/Android 各自降级。
  - **S3**：把 WebView 抽象成自研接口，Android/iOS 用现有插件、ohos 用 `flutter_inappwebview_ohos`——改动最大但隔离最干净。
- **验收**：Android/iOS 构建与全量测试不回归；ohos `flutter pub get` + build 通过。

**候选 fork 源（2026-11 调研，tag 按 Flutter-OH 版本选，如 3.41.9 线选 `*-ohos-1.0.x`）**：

### P4 平台差异文案与信息架构
- **目标**：设置页「平台限制说明」从 iOS 专属升级为「各平台限制说明」，鸿蒙条目如实写（保活/通知/WebView 能力差异）。
- **写集**：`lib/ui/ios_limits_section.dart` → `platform_limits_section.dart`、`lib/l10n/*`（新增 `ohos*` 前缀 key）、引用页 `settings_page.dart`。
- **验收**：Android 不显示、iOS/鸿蒙各显各自条目；l10n 生成产物同批重跑（L14）。

### P5 CI / 发布接入（用户明确要求：CI 要改，允许推送触发）
- **目标**：新增 ohos 构建腿，push 即触发；Release 产出 hap 资产。
- **写集**：`.github/workflows/ci.yml`（新增 `ohos` job，触发含 push main / PR / workflow_dispatch）、`.github/workflows/release.yml`（新增 `hap` job + publish 下载/改名/上传）、`.github/release-notes/` 模板按需。
- **内容**：
  - CI `ohos` job：ubuntu runner 装 OpenHarmony/Flutter-OH 工具链 → `flutter pub get` → `flutter build hap --release --no-codesign`（或签名，若 secrets 齐）→ upload-artifact。
  - Release `hap` job：与 apk/ipa 并行，产物改名 `ZRemoteX-v<版本>-ohos.hap`，`publish` needs 补 `hap`。
  - **推送触发**：`ci.yml` 已含 push main；ohos job 复用同一触发器，另在 release 的 tag 触发中产出 hap。
- **验收**：CI 全绿（或 ohos 腿失败可定位）；Release 资产含三平台。

### P6 真机验证与收口
- 鸿蒙真机/模拟器安装 hap，走查：登录、扫码导入、会话、领取、额度、通知、深链。

## 4. 风险与红线

| 风险 | 等级 | 缓解 |
|---|---|---|
| Flutter-OH 是社区分叉，版本/插件 tag 变化快 | 高 | 锁定 tag 到具体 commit；在本机环境清单记录 SDK 版本与来源 |
| ~~本机无 DevEco/ohos SDK~~（2026-11-16 已装齐：Flutter-OH SDK + 命令行工具 6.1.1.280，hap 构建通过） | 已解决 | 本机环境清单已登记路径/版本/排雷；P6 真机仍无设备 |
| CPF 3.41 嵌入层 `OhosAutoFillHelper` 引用公开 SDK 未导出的 `autoFillManager` 类型（15 个 ArkTS 编译错误） | 高 | `tool/patch_ohos_autofill.py` 降级为 `any`（Autofill 在 api<26 运行时短路）；每次 pub get/build 前重跑；上游修复后移除 |
| git fork 替换插件可能打破 Android/iOS（尤其 inappwebview MULTI_PROFILE） | 高 | P3 单列，Android/iOS 全量测试作回归门禁；不通过则回退 S3 |
| CI ohos 腿在 runner 上装工具链耗时/易碎，拖红整轮 CI | 中 | 先加独立 workflow 或独立 job；失败可定位；不阻塞 verify 结论 |
| 签名/hap 可安装性未验证 | 中 | 先 `--no-codesign` 出包；签名作为 P6 子项 |
| 「全面支持」被误解为含 HarmonyOS 4.x | 低 | 本计划明确 4.x 已兼容 APK，不重复造轮子 |

**红线**（沿用 AGENTS.md / 规范）：
- 不 push、不建 tag、不发 Release（除非用户明确授权）。
- 改注入 JS 同批跑 `hook_script.test.mjs` 与语法测试（M0）。
- 推送前本地 `flutter analyze` 零问题 + `flutter test` 全量绿（L9/S11）。
- 平台分支改动不得让 Android/iOS 回归。

## 5. 验收清单（总）

1. `Platform.isOhos` 之类的 stock 不存在 API **零使用**；平台判定统一走 `PlatformCaps`。
2. Android/iOS 构建与全量测试不回归（analyze 零问题 + test 全绿，读数可复核）。
3. `ohos/` 工程在 CPF-Flutter SDK 下可 `flutter build hap`（签名前至少 debug/unsigned）。
4. CI 在 push 时触发 ohos 构建；Release 产出 `ZRemoteX-v<版本>-ohos.hap`。
5. 鸿蒙真机走查核心链路（登录/导入/会话/领取/额度/通知/深链）——未验证项如实标 not run。
6. 文档三件：索引行、CHANGELOG `[Unreleased]`、LESSONS（如复发）。
