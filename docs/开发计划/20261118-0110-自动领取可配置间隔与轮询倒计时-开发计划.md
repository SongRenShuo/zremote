# 开发计划：自动领取可配置轮询间隔 + 轮询倒计时/进度可视化

> 版本基准：main（探查时 HEAD `6fd7581` 之后，v2.2.1 已发行）
> 目标：①自动领取轮询间隔从写死 10 分钟改为**每设备可配置**（1–120 分钟）；②设备领取页自动领取卡新增**倒计时 + 进度条动画**，让"下次检查还有多久"可见。
> 状态：已立项待实施（本计划经用户确认后同批实施并发布）
> 关联调研：zcode-switch 对照（2026-11-18 主控探查，见 §2）；`20261116-2341`（自动轮初版）、`20261117-1230`（单层总闸/激活前置）。

---

## 1. 现状

- 轮询间隔写死 10 分钟 ± 20% 抖动（`ClaimSchedulerPolicy.roundInterval` + `roundIntervalJittered`，`lib/services/claim_scheduler.dart:11-55`），不可配置。
- 轮询状态对用户不可见：冷却截止有 snapshot（`cooldownUntil`），但"下次检查何时"没有出口；用户只能看到阻断历史推断轮询在跑。
- zcode-switch 对照：间隔同样写死 10 分钟（`main.js:19 AUTO_CLAIM_INTERVAL_MS`）；仅有状态文本（「本轮进行中」+ 上次轮询时间/领取数，`main.js:120-135 autoPillTitle` + 1s ticker），**无倒计时数字、无动画边框**——本计划的可视化是新设计。

---

## 2. 方案（G1–G4）

| # | 内容 | 细节 |
|---|---|---|
| **G1** 间隔可配置（数据层） | `ClaimAutoConfig` 加 `intervalMinutes`（默认 10，clamp [1,120]，int；JSON 键 `intervalMinutes`；copyWith/==/hashCode/toJson/fromJson 同步；旧数据无键回落 10——升级零回归） | `lib/services/claim_scheduler.dart` |
| **G2** 间隔生效（调度层） | `ClaimSchedulerPolicy.roundIntervalJittered` 增加 `baseMinutes` 必填参数（`[0.8×base, 1.2×base]` 抖动）；agent 轮后等待与门控后重算均用 `_config.intervalMinutes`；既有测试按新签名更新（M2 同族） | 同上 + `test/claim_scheduler_test.dart` |
| **G3** 下次检查时间出口（可观测） | agent 新增 `nextRoundAt`：①轮结束 = now + jittered interval；②门控等待中 = 门开时刻（静默结束/冷却截止/manual 冷却截止取最早）；③`snapshot()` 暴露；未 start/停表 = null | `claim_scheduler.dart`、`claim_scheduler_hub.dart`（snapshot 透传） |
| **G4** UI：间隔选择 + 倒计时/进度（领取页） | ①静默时段设置弹层加「轮询间隔」行（选项 1/2/5/10/15/30/60/120 分钟，`Zr` 同款行样式）；②自动领取卡显示倒计时（`nextRoundAt - now`，每秒 tick）+ 细进度条（0→1 随剩余时间递减，`LinearProgressIndicator`）；③自动轮在飞时显示「检查中…」spinner；④门控等待时显示原因（静默至 HH:mm / 冷却至 HH:mm）；⑤1s Timer 仅在 auto 开启且页面挂载时运行（dispose 取消） | `lib/ui/claim_page.dart`、`lib/l10n/*.arb` |

**范围裁定**：间隔与倒计时均 **per-device**（自动领取是设备级语义，与静默时段同层）；设置页全局开关卡不加倒计时（多设备各自 nextAt 无单一值）。

## 4. 验收

- **间隔可配置**：①改间隔为 1 分钟 → 轮询 1 分钟±20% 触发（测试断言）；②旧数据无键回落 10 分钟（升级零回归）；③间隔随设备持久化往返一致。
- **倒计时/进度**：①auto 开启且 live → 卡片显示倒计时递减 + 进度条推进；②轮在飞 → 「检查中…」；③门控等待 → 显示静默/冷却原因与时刻；④auto 关闭 → 倒计时区域隐藏。
- **反向验证（S2）**：摘掉 jittered 的 baseMinutes 传参，间隔用例变红。
- **回归**：单设备手动领取、一键领取、阻断历史、静默时段、激活前置不回归；既有 jitter 边界用例按新签名改写后全过。
- **测试纪律**：定向判据数（S3）+ 全量 `flutter test` + `flutter analyze` 零问题（S11）。
- **not run**：真机长时观察轮询节奏（1s UI tick 属页面级，模拟器走查覆盖）。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| R1 间隔过短（1 分钟）打爆宿主接口 | clamp 下限 1 分钟 + 每轮上限 5 + 失败冷却机制本就存在；文案注明"过短可能触发风控" |
| R2 nextRoundAt 与门控/手动让位竞态 | 门控等待时 nextRoundAt 取门开时刻；手动让位只影响当轮，下轮重算 |
| R3 1s tick 的页面性能 | 仅 auto 开启时运行、单 setState 局部刷新、dispose 取消 |

---

## 6. 不在本轮

- 全局（多设备聚合）倒计时展示。
- 轮询间隔的失败自适应（如连续失败自动拉长间隔）——现有冷却机制已覆盖。
- zcode-switch 同步该功能（独立项目）。
