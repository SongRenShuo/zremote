> 日期：2026-11-15 02:50
> 状态：已完成（2026-11-15，T1-T6 全部落地；本地 667 例全绿 + analyze 零问题）
> 关联：功能工具箱 → 模型设置 → 供应商列表 → 点供应商 → 模型列表
> 用户提供截图：magpie 供应商 21 个模型，名称列被挤压成 "au…" / "re…"

## 1. 问题描述

模型列表（`_ProviderDetailSheet` 内 `_modelRow`）中，模型名称在真机上被截断为
两个字母 + 省略号，且无法左右滑动查看全名。两轮修复（`b5aa5fd` 名称单元格内嵌
横向 SingleChildScrollView、`13b2418` 触摸区加高到整行 32px）后真机依旧拖不动。

## 2. 根因分析（代码实证）

`_modelRow` 是**单行 Row 布局**：

```
Row(
  Expanded(名称列),          ← 弹性宽度
  HwChip(上下文窗口),         ≈ 85dp（"上下文窗口: 1.0M"）
  SizedBox(测试按钮 76dp),
  SizedBox(开关 52dp),
  SizedBox(编辑 30dp, 条件),
  SizedBox(删除 30dp, 条件),
)
```

真机屏宽 ~360dp − sheet 左右 padding 32dp = **328dp 可用**；
固定控件合计 ≈ **289dp**（chip 85 + 间距 10 + 测试 76 + 间距 6 + 开关 52 +
间距 6 + 编辑 30 + 删除 30）→ **名称列只剩 ~35dp ≈ 3 个字符宽**。

由此推出前两轮修复失效的真因：

| 轮次 | 修法 | 为什么没用 |
|---|---|---|
| `b5aa5fd` | 名称单元格内嵌横向 SingleChildScrollView | 滑动区只有 ~35dp 宽——手指完整覆盖它，任何轻微纵向偏移都让手势竞技场把拖动判给外层竖向列表（`SingleChildScrollView`@1407）；且起滑点稍偏出 35dp 就完全落空 |
| `13b2418` | 触摸区加高到整行 32px | 只解决了"高度"，**宽度 35dp 的问题原样存在**；横向拖动的可用起滑面依旧趋近于零 |

结论：**问题不在滑动组件本身，在布局——长名变量宽与 5 个固定控件挤在同一行，
名称列在手机屏上物理性地放不下可用滑动面。** 行内补丁无解，必须重排布局。

## 3. 修复设计（两行卡片重构）

`_modelRow` 从单行 Row 改为两行卡片：

```
Column(
  ── 第一行：模型名（占满整行宽度 328dp）
  │   · 横向 SingleChildScrollView（名字超宽时可左右滑动，滑动面 = 整行）
  │   · 未溢出时静止；溢出时右缘淡出渐隐提示可滑
  │   · 点击名称 → 浮层展示全名（兜底通路，滑动不了的极端情况仍可查看）
  ── 第二行：控件行
      HwChip(上下文窗口) + Spacer + 测试按钮 + 开关 + 编辑 + 删除
）
```

要点：

1. 滑动面从 35dp → **整行 328dp**，起滑点随便选；
2. 控件独占一行，不再挤压名称；
3. 双通路保底：滑动 + 点击浮层；
4. 溢出才显示滑动暗示（右缘 12px 渐变遮罩），未溢出不误导。

## 5. 验收标准

1. 真机（~360dp 宽）上模型名称完整可读：默认放下能看大半，左右滑动看全名；
2. 滑动手势在名称行**任意横向位置**起滑均有效；
3. 点击名称弹出全名浮层（兜底通路可用）；
4. 控件行（上下文 chip/测试/开关/编辑/删除）功能不回归；
5. 本地 666+ 例全绿 + analyze 零问题。

- 测试视口（800×600 逻辑 dp）远宽于真机，widget 测里名称可能不溢出——
  滑动断言用「构造超长 modelId 的 fixture」强制溢出。
- 开源版参考（用户指定 `E:\code\Java\Github\other\ZCode`）桌面端宽屏无此问题，
